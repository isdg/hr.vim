*hr.txt*  A reading-list sidebar backed by the `hr` CLI       *hr* *hr.vim*

==============================================================================
INTRODUCTION                                                    *hr-intro*

hr.vim is a thin sidebar over the `hr` reading-list CLI. It lists articles,
opens them in the main window, and maps a few keys to mark read/unread,
favorite, alias, sync, and refresh. Pure Vimscript — works in Vim 8.1+ and
Neovim.

==============================================================================
CONFIGURATION                                                   *hr-config*

Set these globals before the plugin loads (or any time; they are read live):

                                                                *g:hr_binary*
g:hr_binary     CLI name or path.                       Default: "hr"

                                                                *g:hr_vault*
g:hr_vault      Vault directory. When empty, the vault is read from the
                `vault = "..."` line in hr's config, ~/.hr/config.toml
                ($HR_HOME), and the plugin :cd's into it.
                When set, it is passed to the CLI as `-C <vault>`.
                                                        Default: "" (use rc)

                                                                *g:hr_side*
g:hr_side       Sidebar side: "left" or "right".        Default: "left"

                                                                *g:hr_width*
g:hr_width      Sidebar width in columns.               Default: 60

                                                                *g:hr_show_read*
g:hr_show_read  1 to include read items, 0 for unread only.
                                                        Default: 1

                                                                *g:hr_filter*
g:hr_filter     Extra `hr list` flags scoping the panel: a list
                (['--group', 'books']) or a whitespace-separated string
                ('--group books'). hr owns the flag vocabulary — the plugin
                only forwards — so anything `hr list` accepts works, e.g.
                --group, --feed, --tag, --since, --fav, --bookmarked,
                --corrupted. See
                |hr-filter|.                              Default: []

                                                            *g:hr_track_opens*
g:hr_track_opens  1 to log every vault article loaded into a buffer with
                `hr opened`, which is what `hr recent` lists. 0 stops it.
                See |hr-recent|.                          Default: 1

                                                                *g:hr_resume*
g:hr_resume     1 to put the cursor on an article's bookmark when the
                article loads into a buffer, 0 to stay at the top and
                jump with |:HrResume|. See |hr-bookmarks|.  Default: 1

                                                            *g:hr_corrupt_maps*
g:hr_corrupt_maps   1 to install the buffer-local corruption-marking keys on
                    articles opened from the panel, 0 to bind them yourself
                    via the <Plug> maps below.           Default: 1

                                                          *g:hr_corrupt_prefix*
g:hr_corrupt_prefix Key prefix for those buffer-local maps.
                                                        Default: "<leader>n"

==============================================================================
FILTER                                                            *hr-filter*

The panel can be scoped to part of the vault by passing `hr list` flags,
either as command arguments or via |g:hr_filter|: >

    :Hr --group books                 one shelf
    :HrStart --feed matklad,danluu    one or more authors
    :HrFilter --group sites --unread  flags compose
    :HrFilter -                       drop the scope
    :let g:hr_filter = ['--group', 'humans']
<
The plugin does not interpret these flags; it appends them to `hr list
--json`, so the CLI is the single authority on what they mean and no plugin
change is needed when hr grows a new one. An unknown flag surfaces as an
hr error message.

A scoped panel shows the filter in its buffer name
(`hr://reading-list --group books`), so a narrow view is distinguishable
from a vault that lost its articles. The filter cannot be shown in the
buffer itself, because each line maps positionally to an item.

|:HrLocate| deliberately searches the *unscoped* vault. If the article it
finds has no row in the scoped view, the filter is dropped for the session
so the cursor has somewhere to land — the same trade |g:hr_show_read| makes
for read items.

==============================================================================
VIEWS                                                              *hr-views*

The panel shows one view at a time: the plain list or one of these, switched
from the panel keys or from anywhere with |:HrView|:

    t   :HrView recent         what you opened, see |hr-recent|
    F   :HrView --fav          favorites only
    B   :HrView --bookmarked   bookmarked only, see |hr-bookmarks|

Views replace each other rather than stack: F under recent shows all your
favorites, not the recent ones. Switching to the view already shown returns
to the plain list. The other flags in the filter, the scope set with
|:HrFilter| or `hrv`, stay. Switching opens the panel if it is closed and
focuses it, and puts the cursor on the article you were on, the panel row
or the article being read, when the new view lists it.

==============================================================================
RECENT                                                            *hr-recent*

A leading `recent` switches the panel from `hr list` to `hr recent`: the
articles you opened, most recently opened first, dated by the open. The
other flags still scope it, and --since then means opened within: >

    :Hr recent                        everything you opened
    :HrStart recent --since 7d        this week's reading
    :HrFilter recent --group humans   one shelf
<
In the panel, `t` switches between the list and this view, see |hr-views|.

Opens are logged by an autocmd on |BufReadPost| for *.md files under a
vault's feeds/, running `hr opened` in the background. Loading a buffer is
what counts: switching back to one already loaded does not, and |:edit!|
does. The recent view ignores |g:hr_show_read|. Set |g:hr_track_opens| to 0
to stop logging. With lazy-loading, load the plugin on BufReadPost *.md
too, or opens made before the first :Hr command go unrecorded.

==============================================================================
BOOKMARKS                                                      *hr-bookmarks*

A bookmark is where you stopped reading an article: one per article, kept by
`hr bookmark` in this machine's ~/.hr/<vault>/bookmarks.jsonl. The log is
append-only, so every move of a reading place stays on record; the latest
entry wins. >

    :HrBookmark                       save the cursor as the reading place
    :HrBookmark!                      drop it
    :HrResume                         jump back to it
<
When a vault article loads into a buffer — from the panel, the shell or
anywhere else — the cursor goes to its bookmark (see |g:hr_resume|). That
happens once per buffer, so |:edit!| leaves the cursor where it is. Jumps
leave an entry in the |jumplist|, so CTRL-O returns.

Bookmarked rows show a B in the panel's state column, and `B` there toggles
a bookmarked-only view (`--bookmarked`).

No key is bound by default; bind the <Plug> targets yourself: >
    nmap <leader>nb <Plug>(HrBookmark)
    nmap <leader>nB <Plug>(HrResume)
<
==============================================================================
COMMANDS                                                        *hr-commands*

:Hr  :HrToggle          Toggle the sidebar. When opening, closes all other
                        windows so the feed is the only one (modified buffers
                        are hidden, not lost). Use :HrOpen to keep them.
:HrOpen                 Open the sidebar (focus it if already open). Leaves
                        existing windows untouched.
:HrClose                Close the sidebar.
:HrStart                Open panel only; close the initial empty [No Name]
                        window if present. Entry point for the `hr` CLI.
:HrRefresh              Re-fetch and redraw the list.
:HrSync                 Run `hr sync`, then refresh.

:Hr, :HrToggle, :HrOpen and :HrStart all accept optional `hr list` flags
that scope the panel — `:Hr --group books`, `:HrStart --feed matklad
--unread`. Passing none leaves the current scope alone, so a bare :Hr keeps
toggling the view you set up. See |hr-filter|.

:HrView {view}          Switch the panel to a view (recent, --fav,
                        --bookmarked), or back to the plain list when it
                        is already shown. See |hr-views|.

:HrFilter [flags]       Set the flags scoping the panel, applying them at
                        once when it is open. With no arguments, report the
                        current filter; with a lone `-` or `clear`, drop it.

                                                            *hr-corrupt-commands*
Run these from within an opened article (any saved .md buffer):

:[range]HrCorrupt [note]  Mark the selected region as corrupted (an LLM can
                        repair it later via `hr corrupt restore`). Use it from
                        a visual selection — `:'<,'>HrCorrupt OCR garble`. The
                        exact selection is sent to the CLI, which rejects the
                        mark if it doesn't match the computed byte range.
:HrCorruptUndo          Remove the most recent corruption mark on the article.
:HrBookmark[!]          Save the cursor as the article's reading place; with
                        ! drop it. See |hr-bookmarks|.
:HrResume               Jump to the article's reading place.
:HrLocate               Close this article's window and jump the cursor to its
                        row in the feed panel (opening the panel if closed), so
                        you can act on it there. See |hr-locate|.

==============================================================================
CORRUPTION MARKING                                              *hr-corrupt*

Select garbled text in an article and mark it so tooling can restore it from
the stored quote + surrounding context. Marks live in the article's sidecar;
`hr corrupt list --all --json` is the unified report a repair tool consumes.

Buffer-local keys on articles opened from the panel (see |g:hr_corrupt_maps|,
|g:hr_corrupt_prefix|; shown with the default "<leader>n" prefix):

  <leader>nc   (visual) mark the selection corrupted
  <leader>nn   (visual) mark the selection, prompting for a note
  <leader>nu   (normal) undo the most recent mark

To bind your own keys, map the <Plug> targets (available everywhere): >
    xmap <leader>x  <Plug>(HrCorrupt)
    xmap <leader>X  <Plug>(HrCorruptNote)
    nmap <leader>xu <Plug>(HrCorruptUndo)
<

==============================================================================
LOCATE IN FEED                                                  *hr-locate*

From any saved article buffer — however it was opened — |:HrLocate| (or the
<Plug>(HrLocate) target) checks whether the file belongs to the feed. If it
does, the article's window is closed, the panel is opened (when closed) and
the cursor jumps to the article's row, so you can manage it there — mark read,
favorite, alias — without scrolling to find it. If it does not, nothing
happens beyond a message; no window is closed and no panel is opened.
Membership is checked before any window is touched.

No key is bound by default; bind the <Plug> target yourself, e.g.: >
    nmap <leader>nf <Plug>(HrLocate)
<
Membership is checked against the full list, so a read article is found even
under an unread-only view (|g:hr_show_read| is 0). Locating a read one in that
case turns |g:hr_show_read| on for the session, since the cursor can only land
on a row the panel actually renders.

==============================================================================
SIDEBAR KEYS                                                    *hr-keys*

Active only inside the sidebar buffer:

  <CR>, o     open the article under the cursor
  r           toggle read / unread
  u           mark unread
  f           toggle favorite
  a           set alias (rename the displayed label)
  t           flip between the list and the recent view, see |hr-recent|
  F           toggle `--fav` in the filter: favorites only
  B           toggle `--bookmarked` in the filter: bookmarked only
  R           refresh
  s           sync + refresh
  q           close panel
  ?           show this key list

==============================================================================
EXAMPLE                                                         *hr-example*

Neovim (Lua): >
    vim.g.hr_width = 50
    vim.keymap.set("n", "<leader>r", "<Cmd>HrToggle<CR>",
       { desc = "Toggle hr reading list" })
<
Vim (Vimscript): >
    let g:hr_width = 50
    nnoremap <leader>r <Cmd>HrToggle<CR>
<
